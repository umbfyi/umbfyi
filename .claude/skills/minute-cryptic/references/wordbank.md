# Answer word bank

Starting points, not a closed list. Any word an Umbraco developer would recognise is fair. Check the spelling and enumeration of product names before using them (e.g. "Block Grid" is (5,4)).

## Umbraco
- Product and community: UMBRACO, CODEGARDEN, BELLISSIMA, HEARTCORE, UMBRACIAN, MVP
- Backoffice: BACKOFFICE, DOCTYPE, DATATYPE, TEMPLATE, PARTIAL, COMPOSITION, ELEMENT, SECTION, DASHBOARD, TREE
- Content model: CONTENT, MEDIA, MEMBER, DICTIONARY, BLOCK LIST, BLOCK GRID, PROPERTY, EDITOR, NODE, PUBLISH
- Products: FORMS, DEPLOY, WORKFLOW, COMMERCE, CLOUD
- Extending: PACKAGE, PLUGIN, COMPOSER, MANIFEST, EXTENSION, NOTIFICATION

## .NET and web tech
- .NET: NUGET, RAZOR, BLAZOR, CSHARP (clue as C SHARP or avoid), LINQ, ASSEMBLY, MIDDLEWARE, CONTROLLER
- Front end: LIT, VITE, TYPESCRIPT, BROWSER, COOKIE, PIXEL, WIDGET, CANVAS, FONT
- Back end and infra: SERVER, AZURE, DOCKER, CONTAINER, DATABASE, INDEX, QUERY, SCHEMA, ENDPOINT

## Coding life
- Workflow: COMMIT, BRANCH, MERGE, REBASE, FORK, CLONE, PULL, PUSH, RELEASE, HOTFIX, ROLLBACK, STANDUP, SPRINT, BACKLOG
- Code: LOOP, ARRAY, STRING, CLASS, METHOD, OBJECT, BOOLEAN, NULL, VARIABLE, CONSTANT, LAMBDA, SYNTAX, COMPILER
- Debugging: BUG, DEBUG, ERROR, CRASH, PATCH, LOG, TRACE, EXCEPTION, TIMEOUT
- Git: HEAD, STASH, TAG, BLAME, DIFF, FETCH (most have everyday meanings: top, hoard, label, fault, bring)
- Web requests: GET, PUT, POST, PATCH, DELETE, HEAD (everyday English too, so good for double definitions)
- Data: BIT, BYTE, NIBBLE (half a byte, and a small bite)

## Phrases
Multi-word answers are welcome. Write the answer with spaces and the verifier checks the enumeration, e.g. "I REMEMBER BEING DIRTY" is (1,8,5,5). Use hyphens for hyphenated answers, e.g. "HIGH-FIVE" is (4-4).

### Umbraco
FRIENDLY CMS, BLOCK LIST, BLOCK GRID, DOCUMENT TYPE, DATA TYPE, ELEMENT TYPE, PROPERTY EDITOR, PARTIAL VIEW, UMBRACO CLOUD, HIGH FIVE YOU ROCK

### Umbraco codebase names read as sentences
C# interface names split into words make fun answers. Define them as what the code does ("entity tracking its changes"), and say "Umbraco interface" in the hints so solvers know where to look.
- I REMEMBER BEING DIRTY (1,8,5,5): `IRememberBeingDirty`, an entity that remembers its changes after saving
- I CAN BE DIRTY (1,3,2,5): `ICanBeDirty`, an entity that tracks property changes
- SHORT STRING HELPER (5,6,6): `IShortStringHelper`, makes URL segments and aliases

Before using any other codebase name, confirm it exists in the umbraco/Umbraco-CMS repo (e.g. GitHub code search for `"interface IName" repo:umbraco/Umbraco-CMS`). Never invent one; a made-up interface in a public newsletter will be spotted.
